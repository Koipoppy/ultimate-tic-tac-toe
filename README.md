# 双层井字棋 LAN联机对弈

> Ultimate Tic-Tac-Toe · 基于 WebRTC 的纯HTML局域网联机对弈游戏

---

## 📖 项目简介

一款**双层九宫格结构**的高级井字棋游戏。棋盘为 3×3 的大九宫格，每个大格内嵌 3×3 的小九宫格，共 **81 个落子位**。

两名玩家仅需打开同一个 `index.html` 网页，通过 **4 位房间码**即可建立 P2P 直连，实现局域网实时对弈。无需安装任何软件，无需搭建服务器。

---

## 🎮 游戏规则

### 棋盘结构

```
┌─────────────┬─────────────┬─────────────┐
│ ┌───┬───┬─── │ ┌───┬───┬─── │ ┌───┬───┬─── │
│ │   │   │   │ │   │   │   │ │   │   │   │ │
│ ├───┼───┼─── │ ├───┼───┼─── │ ├───┼───┼─── │
│ │   │   │   │ │   │   │   │ │   │   │   │ │
│ ├───┼───┼─── │ ├───┼───┼─── │ ├───┼───┼─── │
│ │   │   │   │ │   │   │   │ │   │   │   │ │
│ └───┴───┴─── │ └───┴───┴─── │ └───┴───┴─── │
├─────────────┼─────────────┼─────────────┤
│      ...    │     ...     │     ...     │
├─────────────┼─────────────┼─────────────┤
│      ...    │     ...     │     ...     │
└─────────────┴─────────────┴─────────────┘
```

外层粗线 = 大九宫格（3×3），每个格子内部 = 小九宫格（3×3）

### 核心规则：禁入机制

> **"落子定禁区"** — 反向终极井字棋

- 玩家 A 在某个小九宫格的**位置 (r, c)** 落子后
- 玩家 B **禁止**在大九宫格的**位置 (r, c)** 对应的全部 9 个小格子中落子
- 若禁入区域已归属某玩家或已满（平局），则禁入限制**自动解除**，可自由选择

**示例：**
> 你在小九宫格的第 1 行第 2 列落子 → 对方本回合不可在大九宫格第 1 行第 2 列的整个区域落子

### 胜负判定

| 层级 | 条件 | 结果 |
|------|------|------|
| **小格胜负** | 小九宫格内三连（横/竖/斜） | 该大格归属对应玩家 |
| **终局胜负** | 大九宫格整体三连（横/竖/斜） | 该玩家获得本局胜利 |
| **平局** | 所有大格均有归属且无大格三连 | 本局平局 |

## 🚀 快速开始

### 方式一：直接打开（推荐）

1. 两名玩家各自用浏览器打开 `index.html`
2. 玩家一：输入昵称 → 点击 **「创建房间」** → 获得 4 位房间码
3. 玩家二：输入昵称和房间码 → 点击 **「加入房间」**
4. 连接建立，开始对弈！

### 方式二：局域网服务器

```bash
# 任意 HTTP 服务器均可
npx serve .
# 或
python -m http.server 8080
```

然后用局域网 IP 访问（如 `http://192.168.1.100:8080`）

## 🛠 技术架构

| 模块 | 技术方案 |
|------|----------|
| **网络通信** | WebRTC (PeerJS) — P2P 直连 |
| **信令服务** | PeerJS Cloud Server（仅握手阶段） |
| **游戏逻辑** | 纯 JavaScript 状态机 |
| **界面渲染** | 原生 DOM + CSS3 动画 |
| **部署方式** | 单 HTML 文件，零依赖安装 |

### 通信协议

```
Host (先手 ✕)                    Guest (后手 ○)
     │                                │
     │──── create room ────────────→  │
     │←─── join room + connect ────  │
     │                                │
     │──── game_state (全量同步) ──→  │
     │                                │
     │  [Host 落子：本地更新 + 同步]   │
     │──── game_state ─────────────→  │
     │                                │
     │              [Guest 落子]       │
     │←─── move (li, si) ──────────  │
     │  [Host 处理 + 同步]            │
     │──── game_state ─────────────→  │
     │                                │
```

## 🔧 已知限制 & 注意事项

1. **首轮握手需要互联网**：PeerJS 信令服务器用于建立初始连接，连接建立后转为纯 P2P 局域网通信
2. **NAT 穿透**：同局域网内基本无障碍；跨 NAT 可能需要 STUN/TURN 服务器
3. **房间码唯一性**：相同房间码同时只能有一组对局
